# 🛠️ バックエンド・リファレンス：Domain Layer (ドメイン層)

ドメイン層は，システムの核心となる業務規則，実体（エンティティ），および外部技術に依存しない抽象的な約束事（インターフェース）を定義する．

---

## 📂 entities (実体定義)

データの構造と検証規則（Zod）の詳細仕様である．

### `Badge.ts` (標本基本定義)

標本（アート作品）の情報を定義する．

#### `BadgeSchema`

データベースへの保存時やAPI通信時に，データの構造と検証規則を保証するための設計図である．

| 属性名         | 型       | 説明・検証規則                                                      |
| :------------- | :------- | :------------------------------------------------------------------ |
| `id`           | `UUID`   | 標本を一意に識別する識別子．                                        |
| `name`         | `string` | 作品名．必須項目．システム内で一意（ユニーク）．                    |
| `artist`       | `string` | 作者名．データベースの空値（null）は `undefined` として処理される． |
| `model_url`    | `string` | AR投影用3D模型(.glb)への経路．絶対URLまたは `/` 開始の相対経路．    |
| `image_url`    | `string` | 標本の絵画画像経路．絶対URLまたは `/` 開始の相対経路．              |
| `target_index` | `number` | MindARの標的番号（0〜5の整数）．                                    |
| `created_at`   | `string` | データの登録日時．システムにより自動付与される．                    |

### `Profile.ts` (来場者属性定義)

利用者の属性情報を定義する．

#### `ProfileSchema`

利用者の進行状況や設定を管理するための設計図である．

| 属性名         | 型        | 説明・検証規則                                         |
| :------------- | :-------- | :----------------------------------------------------- |
| `id`           | `string`  | 利用者を一意に識別する識別子．Supabase Auth と紐付く． |
| `party_size`   | `number`  | 来場人数（1〜10名の整数）．統計資料の基礎となる．      |
| `is_exchanged` | `boolean` | 景品交換完了旗（フラグ）．初期値は `false` である．    |
| `created_at`   | `string`  | プロフィールの作成日時．                               |
| `last_seen`    | `string`  | 最終活動日時．更新時に自動で再設定される．             |

#### `UpdateProfileRequestSchema`

API（`/api/v1/profile/update`）への更新要求時に使用される検証設計図である．

| 属性名                 | 型        | 説明・検証規則                                          |
| :--------------------- | :-------- | :------------------------------------------------------ |
| `userId`               | `string`  | 更新対象利用者の識別子．1文字以上の文字列が必須である． |
| `updates`              | `object`  | 更新内容を格納する構造体．以下の任意項目を含む．        |
| `updates.party_size`   | `number`  | (任意) 1〜10 の整数．来場人数の上書きを行う．           |
| `updates.is_exchanged` | `boolean` | (任意) 景品交換完了状態の上書きを行う．                 |

### `UserBadge.ts` (獲得記録定義)

利用者がいつ，どの標本を獲得したかを定義する．

#### `UserBadgeSchema`

誰がいつ何を見つけたかの記録を管理するための設計図である．

| 属性名        | 型       | 説明・検証規則                             |
| :------------ | :------- | :----------------------------------------- |
| `id`          | `UUID`   | 獲得記録固有の識別子（任意）．             |
| `user_id`     | `string` | 獲得した利用者の識別子（必須）．           |
| `badge_id`    | `UUID`   | 獲得された標本の識別子（有効なUUID形式）． |
| `acquired_at` | `string` | 標本の解析が完了し，獲得に至った日時．     |

#### `AcquireBadgeRequestSchema`

フロントエンドからの標本獲得通知（`/api/v1/badges/acquire`）に使用される検証設計図である．

| 属性名    | 型       | 説明・検証規則                                          |
| :-------- | :------- | :------------------------------------------------------ |
| `userId`  | `string` | 獲得した利用者の識別子．1文字以上の文字列が必須である． |
| `badgeId` | `string` | 獲得対象の標本識別子．UUID形式の文字列が必須である．    |

### `ApiCommon.ts` (共通応答形式)

一貫したAPI応答を保証するための定義である．

#### `ApiErrorSchema`

API実行中に異常が発生した際，応答の `error` 項目に格納される構造を定義する．

| 属性名    | 型       | 説明・検証規則                                        |
| :-------- | :------- | :---------------------------------------------------- |
| `code`    | `string` | 異常の分類を識別するための符号（例：`FETCH_ERROR`）． |
| `message` | `string` | 利用者に表示することを想定した，異常の概要説明文．    |
| `details` | `any`    | (任意) 開発時の調査に役立つ詳細情報．                 |

#### `createApiResponseSchema<T>`

一貫した通信を行うため，成功・失敗の判別が可能な共通応答構造を生成する汎用関数である．

- **引数 (`dataSchema`)**：成功時に `data` 項目が保持すべきデータの Zod 設計図を指定する．
- **戻り値**：以下のいずれかの構造を持つ判別共用体を返す．
  - **成功時 (`success: true`)**：`{ success: true, data: T }`
  - **失敗時 (`success: false`)**：`{ success: false, error: ApiError }`

## 📂 repositories (抽象操作定義)

データの永続化に関する抽象的な定義である．具体的な実装は Infrastructure 層で行う．

### `IBadgeRepository.ts`

標本（マスターデータ）の読み取り操作を定義するインターフェースである．

#### `findAll()`

- **引数**：なし
- **戻り値**：`Promise<Badge[]>`（全標本実体の配列）
- **概要**：データベースに登録されているすべての標本情報を，表示順（ターゲット順）に従って取得する．

#### `findById(id)`

- **引数**：`id: string`（標本識別子）
- **戻り値**：`Promise<Badge | null>`（該当する標本実体，存在しない場合は null を返す）
- **概要**：指定された識別子（UUID）に一致する標本を1件取得する．

### `IProfileRepository.ts`

利用者プロフィールに関する操作を定義するインターフェースである．

#### `findById(id)`

- **引数**：`id: string`（利用者識別子）
- **戻り値**：`Promise<Profile | null>`（利用者のプロフィール実体，未作成の場合は null を返す）
- **概要**：利用者識別子（UUID）に基づいてプロフィール情報を照会する．

#### `upsert(profile)`

- **引数**：`profile: Partial<Profile> & { id: string }`（更新または作成する属性情報）
- **戻り値**：`Promise<Profile | null>`（処理後の最新プロフィール実体）
- **概要**：プロフィールの新規作成，または既存情報の更新（来場人数や交換旗など）を一括で行う．

### `IUserBadgeRepository.ts`

標本獲得記録に関する操作を定義するインターフェースである．

#### `create(userId, badgeId)`

- **引数**：
  - `userId: string`（獲得した利用者の識別子）
  - `badgeId: string`（対象となる標本の識別子）
- **戻り値**：`Promise<{ data: UserBadge | null, error: unknown }>`（保存された記録実体と異常情報）
- **概要**：利用者が標本を獲得した事実を永続化する．同一利用者による同一標本の重複獲得は，データベース制約により制限される．

#### `findByUserId(userId)`

- **引数**：`userId: string`（利用者識別子）
- **戻り値**：`Promise<UserBadge[]>`（獲得記録実体の配列）
- **概要**：特定の利用者に紐付くすべての獲得記録を一覧で取得する．

### `IAdminRepository.ts`

管理者向けの広範なデータ操作を定義するインターフェースである．

#### `listAuthUsers()`

- **引数**：なし
- **戻り値**：`Promise<any[]>`（認証システムの利用者目録）
- **概要**：認証基盤（Supabase Auth）から全利用者の情報を取得する．スタッフ（管理者）の除外計算などの基礎資料となる．

#### `getAllProfiles()`

- **引数**：なし
- **戻り値**：`Promise<Profile[]>`（全プロフィール実体の配列）
- **概要**：システムに登録されている全利用者の属性情報を，作成日時の降順で一括取得する．

#### `getBadgesSince(date)`

- **引数**：`date: Date`（抽出開始日時）
- **戻り値**：`Promise<UserBadge[]>`（該当日時以降の獲得記録配列）
- **概要**：特定の期間内（直近1時間や24時間など）に発生した獲得記録をすべて抽出する．

#### `getTotalBadgeCount()`

- **引数**：なし
- **戻り値**：`Promise<number>`（獲得総数）
- **概要**：システム全体で標本が獲得された累計回数を算出する．

## 📂 services (外部機能定義)

### `ICacheService.ts`

揮発性記憶領域（Redis等）を操作するためのインターフェースである．

#### `get<T>(key)`

- **引数**：`key: string`（検索キー）
- **戻り値**：`Promise<T | null>`（保存されていたデータ）
- **概要**：指定されたキーに対応するデータを取得する．

#### `set(key, value, ttl)`

- **引数**：
  - `key: string`（保存キー）
  - `value: any`（保存データ）
  - `ttl: number`（生存時間・秒単位）
- **戻り値**：`Promise<boolean>`（成功可否）
- **概要**：データをキャッシュに保存する．

#### `delete(key)`

- **引数**：`key: string`（削除キー）
- **戻り値**：`Promise<void>`
- **概要**：指定されたキーのデータを破棄する．

## 📂 logic (計算処理)

### `logic.ts`

特定の外部技術に依存しない，純粋な数学的計算や共通の論理を定義する．

#### `calculateProgress(total, acquired)`

- **引数**：
  - `total: number`（全体の数・目標数）
  - `acquired: number`（現在の獲得数・達成数）
- **戻り値**：`number`（0から100の整数で表される進捗率）
- **概要**：全体の目標数と現在の達成状況から，進捗率を算出する．
- **処理詳細**：
  1. **検証**：分母となる `total` が0以下の場合は計算不能と判断し，0を返却する（早期リターン）．
  2. **算出**：`(達成数 / 目標数) * 100` により百分率を算出する．
  3. **補正**：算出結果を四捨五入して整数化し，最終的な値が0から100の範囲内に収まることを保証する．
